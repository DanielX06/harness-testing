HOW TO WORK
1. Read runs.json and dataset.json, then look at the data before fitting anything. Check what moves after each event and on what time scales, how the device's P and Q relate to V, theta and the voltage setpoint, and how large the noise is.
2. Use both kinds of recording. The staged voltage-reference tests show the device's voltage control directly. The ambient recordings and natural events show how it responds to the grid.
3. Propose a candidate structure and fit its parameters on train/, with P and Q as outputs and V, theta and Vset as inputs, the way the scorer uses them.
4. Check each candidate as close to how it will be scored as you can: python tools/grid_equivalent_replay.py submission.json val/<file>.csv. It runs your model against a source behind the network's short-circuit reactance, built from the recording so that the real device would reproduce the recording exactly, so your model's P and Q move V and theta the way the grid does at short time scales. The open-loop replay in tools/check_submission.py holds V and theta at their measured values instead; a model whose control is only damped through the network can diverge there even when it is right, so trust the grid-equivalent numbers when the two disagree. A model that reacts too strongly can still destabilize the full grid.
5. Revise based on what the residuals show, not on the fit score alone. Keep track of which candidates you rejected and why.
6. Stop when the residuals are close to the noise or further terms stop improving the validation fit. Note any parameter that is poorly identified or trades off against another one.
7. Write the model to submission.json. Run python tools/check_submission.py submission.json val/<file>.csv on each validation file to confirm it parses and starts at rest, and python tools/grid_equivalent_replay.py submission.json val/<file>.csv for the errors. Fix anything they report, and then submit.

HOW TO WORK
1. Read runs.json and dataset.json, then look at the data before fitting anything. Check what moves after each event and on what time scales, how the device's P and Q relate to V, theta and the voltage setpoint, and how large the noise is.
2. Run python tools/freq_response.py first. It prints the device's measured small-signal response from V and theta to P and Q (0.1 to 10 Hz) at each quiet recording's operating point. The scorer compares your model's linearized response with the real one on exactly these four channels, so treat these numbers as targets alongside the time series.
3. Use both kinds of recording. The staged voltage-reference tests show the device's voltage control directly. The ambient recordings and natural events show how it responds to the grid.
4. Propose a candidate structure and fit its parameters on train/, with P and Q as outputs and V, theta and Vset as inputs, the way the scorer uses them. The parameter ranges in system.md describe generic models, not this unit: use wide bounds, and if a parameter ends at a bound, widen it rather than accept the bound.
5. Check every candidate two ways before choosing:
   a. replay: drive it with the measured V, theta and Vset from val/, integrate it forward, and compare its P and Q with the measured ones;
   b. python tools/freq_response.py submission.json (save the candidate as a submission first). Look at the MEAN ERROR per channel. If a channel's model gain is several times the data's (or a fraction of it), the structure or a parameter is wrong there even if the replay looks good. Prefer the candidate with the lower overall error when replay errors are similar.
   The scorer runs closed loop, inside the grid. A model that reacts too strongly can destabilize the grid even if it replays well. A model whose Q rises with V at steady state (positive dQ/dV) is positive feedback on the grid voltage; in the recordings Q and V move together because the device moves the grid voltage, so a regression of Q on V shows the grid's slope, not the device's.
6. Revise based on what the residuals and the frequency-response table show, not on the fit score alone. Keep track of which candidates you rejected and why.
7. Stop when the residuals are close to the noise and the frequency-response error stops improving. Note any parameter that is poorly identified or trades off against another one.
8. Write the model to submission.json. Use theta only relative to theta0 or to an angle state whose init contains theta0 (the files start at theta = 0, the scorer does not). Run python tools/check_submission.py submission.json val/<file>.csv on each validation file and python tools/freq_response.py submission.json one last time, fix anything they report, and then submit.
